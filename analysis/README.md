# DStressR Analysis Area

This folder is intentionally outside the CRAN package. `.Rbuildignore`
excludes `analysis/`, so the package submitted to CRAN stays lightweight and
self-contained while the repository can still keep reproducibility and
manuscript workflows nearby.

The guiding rule is that reusable statistical functionality belongs in `R/`
and is tested under `tests/`. Scripts in `analysis/` may call the package,
assemble manuscript figures, compare workflows, or audit external examples,
but they should not become a second implementation of DStressR.

## Layout

- `ecoli_promoter_screen/`: canonical paper-reproducibility workflow for the
  public *E. coli* promoter-compound screen. These scripts generate the
  response-construction, effect-matrix, hit-calling, supplementary, and
  interaction-model outputs used by the DStressR package manuscript.
- `dryad_global_regulators/`: fluorescence/OD regulator-stress example used as
  the second manuscript application. Raw downloaded data stay local under
  `analysis/dryad_global_regulators/raw/`.
- `campylobacter_manuscript/`: earlier downstream Campylobacter comparison
  workflow. This is retained for future analysis work, but is not part of the
  current DStressR package manuscript.
- `exploratory/`: exploratory or candidate datasets that are useful for future
  papers or package examples, but are not part of the canonical manuscript
  workflow.
- `outputs/`: generated local tables and figures. This directory is ignored by
  Git and is not part of the package.

Analysis scripts may consume package outputs, but should not reimplement
estimators, p-value calculations, empirical-Bayes moderation, replicate
aggregation, or multiple-testing correction. If a statistic belongs to the
package API, add it under `R/` and test it under `tests/`.

## Reproducibility Contract

Paper figures are generated by scripts in the dataset-specific analysis
folders and written to `analysis/outputs/`. The manuscript reads these output
files, but the generated outputs themselves stay local by default. This keeps
the GitHub repository focused on code and reproducibility instructions rather
than on large or frequently regenerated artifacts.
